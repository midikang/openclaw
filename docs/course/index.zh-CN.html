第 0 模块

什么是 OpenClaw？

OpenClaw 是一个私有、自托管的 AI 助手，运行在你自己的设备上，通过你已经在用的任意聊天 App 与你对话。

💬

任意渠道

WhatsApp、Telegram、Discord、Slack、Signal、iMessage、微信等 20+ 平台，统一接入一个助手。

🧠

任意模型

Claude、OpenAI、Ollama、本地模型，30+ 供应商，切换模型无需改动其他配置。

🔌

高度可扩展

渠道插件、工具插件、技能插件，不修改核心代码就能添加新能力。

🔒

数据在你手中

运行在你的树莓派、VPS 或 Mac 上。除非你选择云端 AI 供应商，否则数据不会离开本地。

⚡

持续在线

以守护进程（launchd/systemd）方式运行，自动重启、监听配置变更、处理断线重连。

🛠️

工具执行

Bash 命令、文件读写、网络搜索、图片生成，内置审批流程，安全可控。

第 1 模块

网关 — 你的控制中心

网关一个长期运行的 WebSocket + HTTP 服务器（默认端口 18789），是 OpenClaw 所有活动的控制平面。是 OpenClaw 的核心，一个 7×24 小时运行的 WebSocket + HTTP 服务器，负责协调一切。

src/gateway/server.impl.ts
async function startGatewayServer(
  options: GatewayServerOptions
) {
  // 1. 从 ~/.openclaw/config.json 加载配置
  const cfg = await loadConfig();

  // 2. 启动所有已安装的插件
  const runtime = await initPluginRuntime(cfg);

  // 3. 连接所有渠道插件
  const channels = new ChannelManager(cfg, runtime);
  await channels.connectAll();

  // 4. 启动 WebSocket 服务器
  listenWebSocket({ port: options.port ?? 18789 });

  // 5. 启动后台任务
  startHeartbeatRunner();
  startCronScheduler(cfg);
  watchConfigFile(cfg);
}
逐行解释
  • 读取配置文件 ~/.openclaw/config.json，其中包含 Agent、渠道、绑定规则和模型偏好设置。
  • 加载所有已安装的插件（渠道、模型供应商、工具插件），插件是普通的 npm 包。
  • 逐一连接每个渠道：打开 WhatsApp WebSocket、轮询 Telegram、加入 Discord 等。
  • 打开 WebSocket 服务器，让移动 App、CLI 和 Web UI 都能与网关通信。
  • 启动后台任务：心跳包保持渠道连接，Cron 调度器触发定时任务，配置监听器在文件变更时自动重载。

网关的职责

📥 接收消息

从已连接的渠道（WhatsApp、Telegram…）接收消息，判断由哪个 Agent 处理，并放入队列。

📤 发送回复

将 AI 生成的回复格式化后通过对应渠道送达，处理消息分段、媒体附件和正在输入提示。

🔑 身份验证

签发并校验网关令牌。对未认证调用方限速（默认每分钟 10 次）。支持 CLI 通过二维码配对获取设备令牌。

🔄 配置热重载

监听 ~/.openclaw/config.json，文件变更后自动重新连接受影响的渠道，无需重启进程。

⚠️

一台机器只能运行一个网关。如果启动第二个，它会因端口冲突或锁文件而立即退出。

export type ResolveAgentRouteInput = {
  cfg: OpenClawConfig;
  channel: string;       // "telegram"
  accountId?: string;    // 哪个账号
  peer?: RoutePeer;      // 谁发的
  parentPeer?: RoutePeer; // 线程父节点
  guildId?: string;      // Discord 服务器
  memberRoleIds?: string[];
};

export type ResolvedAgentRoute = {
  agentId: string;        // "default"
  sessionKey: string;    // 唯一会话 ID
  mainSessionKey: string; // DM 折叠键
  matchedBy: MatchReason; // 匹配原因
};
逐行解释
  • 输入描述消息来源：哪个渠道（如 "telegram"）、哪个平台账号、哪个用户（peer），以及是否在某个线程内。
  • 输出是一个决策："把这条消息交给 Agent X，使用会话键 Y。"
  • agentId 是应处理此消息的 AI Agent 名称（"default"、"work" 等）。
  • sessionKey 是该对话线程的唯一 ID，Agent 的记忆以此为作用域。
  • matchedBy 告诉你为什么选中了这个 Agent，便于调试（"binding.peer" 表示该用户被显式映射到了某个 Agent）。

src/channels/plugins/index.ts（简化）
type ChannelPlugin = {
  id: string;         // "telegram", "discord"
  connect: (
    cfg: OpenClawConfig,
    onMessage: MessageHandler
  ) => Promise<ChannelConnection>;
  send: (
    connection: ChannelConnection,
    msg: OutboundMessage
  ) => Promise<void>;
  disconnect: () => Promise<void>;
};
逐行解释
  • 每个渠道插件都遵循同一个三方法约定：connect（连接）、send（发送）、disconnect（断开）。
  • connect 建立连接并注册 onMessage 回调——用户发消息时此回调立即触发。
  • send 将 AI 生成的回复送达该平台上对应的用户。
  • disconnect 干净地关闭连接（用于关机或配置重载时）。
  • 网关只调用这三个方法——不需要了解 WhatsApp 和 Telegram 的任何内部实现差异。

测验

用户从 WhatsApp 发消息，两小时后同一用户从 Telegram 发消息。这两次对话会共享记忆吗？

✅ 正确。会话键默认同时包含渠道和用户 ID，因此 WhatsApp 和 Telegram 会产生不同的会话。但如果你配置了将两者映射到同一 Agent + 会话键的 peer 绑定，历史记录就能共享。设计上这是显式选择，不会自动合并。

src/agents/pi-embedded-runner/runs.ts
export function queueEmbeddedPiMessage(
  sessionId: string,
  text: string
): boolean {
  const handle = ACTIVE_EMBEDDED_RUNS.get(sessionId);
  if (!handle) {
    diag.debug(`no active run for ${sessionId}`);
    return false;
  }
  if (handle.isCompacting()) {
    // 正在压缩上下文窗口——等待
    return false;
  }
  void handle.queueMessage(text);
  return true;
}
逐行解释
  • 每个活跃对话都是一个"嵌入式运行"——一个可以在运行期间继续接收消息的 Agent 循环。
  • Agent 正在流式回复时，新消息依然可以到达（如你在回复未完成时发了追问）。它们会按顺序入队处理。
  • 如果 Agent 正在进行上下文压缩（裁剪历史消息以适应上下文窗口），新消息会等待——不丢失，只是短暂暂停。
  • 返回 false 表示消息未入队（没有活跃会话），调用方随后会创建新会话。

测验

用户正在与 Agent 对话，Agent 正在流式输出一段较长的回复。此时用户发送了另一条消息，会发生什么？

✅ 正确。queueEmbeddedPiMessage 将新消息加入活跃运行的内部队列，Agent 在完成当前轮次后立即处理它。这种设计避免了竞态条件，即使消息快速连续到达，对话也能保持连续性。
第 5 模块

插件系统 — 赋予新能力

OpenClaw 的插件系统允许你添加新的渠道渠道插件新增消息平台，位于 extensions/ 目录下，暴露 connect/send/disconnect 接口。、模型供应商、工具和技能，无需修改核心代码。插件就是普通的 npm 包。

extensions/discord/openclaw.plugin.json
{
  "id": "discord",
  "channels": ["discord"],
  "configSchema": {
    "type": "object",
    "properties": {}
  }
}
逐行解释
  • 每个插件通过 JSON 清单文件声明自身：id 是稳定标识符，channels 数组声明此插件提供哪些渠道 ID。
  • 网关读取 channels 数组后，会在对应渠道上调用插件导出的 connect/send/disconnect 方法。
  • configSchema 定义该插件在配置文件中所需的字段结构，用于配置校验。
  • 插件通过 npm 安装到独立的插件目录，不会污染核心安装。

插件生命周期

1
安装
openclaw plugins install <name>——在插件目录中执行 npm install。
2
注册
下次网关启动时，插件加载器扫描插件目录，读取清单，将插件添加到注册表。
3
激活
网关调用插件的 activate(runtime) 导出，注入插件运行时 API：配置、会话、工具、钩子。
4
运行
渠道插件连接到对应平台，工具插件注册工具，钩子插件订阅网关事件。
5
更新 / 移除
openclaw plugins update / openclaw plugins remove <name>，下次网关重启后生效。

插件类型

📡 渠道插件

连接到某个消息平台，提供 connect、send、disconnect。示例：@openclaw/discord、@openclaw/matrix、@openclaw/msteams。

🤖 供应商插件

封装 AI API，将 OpenClaw 的模型接口转换为供应商 SDK。示例：@openclaw/anthropic、@openclaw/amazon-bedrock、@openclaw/deepseek。

🔧 工具插件

向 Agent 添加可调用工具，Agent 可按名称调用。示例：网络搜索、日历集成、自定义 API。

🪝 钩子插件

订阅网关事件：message.in、message.out、session.start、tool.exec。用于日志记录、数据分析、消息转发。

术语表

网关（Gateway）

长期运行的 WebSocket + HTTP 服务器，是 OpenClaw 的控制平面。默认端口 18789，所有渠道、Agent 和客户端都通过它连接。

Agent

命名的 AI 角色，拥有独立的系统提示词、模型选择和对话历史。可为不同场景创建多个 Agent。

渠道插件（Channel Plugin）

连接到某个消息平台的 npm 包，暴露 connect、send、disconnect。所有渠道均为插件，无一硬编码进核心。

会话键（Session Key）

对话线程的唯一标识：agentId:type:channel:peerId。Agent 的记忆以此为作用域，不同键意味着独立记忆。

绑定（Binding）

将用户（peer）、群组（guild）或渠道映射到特定 Agent 的配置规则。优先级高的规则优先匹配，未命中任何规则则路由到默认 Agent。

嵌入式运行（Embedded Run）

带有实时 AI 循环的活跃 Agent 会话，流式输出期间可继续接收新消息。每个会话键最多同时存在一个嵌入式运行。

上下文压缩（Context Compaction）

对话超出 AI 模型上下文窗口时，将旧轮次总结压缩并裁剪记录。对话无缝继续，不丢失数据，只是做了压缩。

ACP（Agent 控制平面）

从父 Agent 派生子 Agent（子 Agent）的系统，用于并行处理或专项任务。结果流回父会话。
