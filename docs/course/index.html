What is OpenClaw?

OpenClaw is a personal, self-hosted AI assistant that lives on your own machine and talks back on any messaging app you already use.

💬

Any Channel

WhatsApp, Telegram, Discord, Slack, Signal, iMessage, Teams, Matrix, and 15+ more — all connected to one assistant.

🧠

Any Model

Claude, OpenAI, Ollama, local models, 30+ providers. Switch models without changing anything else.

🔌

Extensible

Channel plugins, tool plugins, skill plugins — add new abilities without touching core code.

🔒

Your Infrastructure

Runs on your Raspberry Pi, VPS, or Mac. No data leaves unless you choose a cloud AI provider.

⚡

Always On

Runs as a daemon (launchd/systemd). Auto-restarts, watches config, handles reconnects.

🛠️

Tool Execution

Bash commands, file reads, web search, image generation — with approval flows built in.

MODULE 1

The Gateway — Your Control Center

The gatewayA long-running WebSocket + HTTP server (port 18789 by default) that is the control plane for all of OpenClaw's activity. is the heart of OpenClaw. It is a WebSocket + HTTP server that stays running 24/7 and coordinates everything.

src/gateway/server.impl.ts
async function startGatewayServer(
  options: GatewayServerOptions
) {
  // 1. Load config from ~/.openclaw/config.json
  const cfg = await loadConfig();

  // 2. Boot all installed plugins
  const runtime = await initPluginRuntime(cfg);

  // 3. Connect every channel plugin
  const channels = new ChannelManager(cfg, runtime);
  await channels.connectAll();

  // 4. Start WebSocket server
  listenWebSocket({ port: options.port ?? 18789 });

  // 5. Schedule background tasks
  startHeartbeatRunner();
  startCronScheduler(cfg);
  watchConfigFile(cfg);
}
Plain English
  • Read the user's configuration file from ~/.openclaw/config.json — this is where agents, channels, bindings, and model preferences live.
  • Load every plugin that's installed (channels, model providers, tool plugins). Plugins are npm packages installed into a plugins directory.
  • Connect to every channel: open the WhatsApp websocket, poll Telegram, join Discord, etc.
  • Open a WebSocket server so the mobile app, CLI, and web UI can all talk to the gateway.
  • Start background jobs: heartbeats keep channel connections alive, the cron scheduler fires timed tasks, and the config watcher reloads when the file changes.

What the Gateway Handles

📥 Inbound

Receives messages from connected channels (WhatsApp, Telegram…), determines which agent should handle them, and queues them for the agent runner.

📤 Outbound

Takes the AI's reply, formats it for the channel, and delivers it back — handling message splitting, media attachments, and typing indicators.

🔑 Auth

Issues and verifies gateway tokens. Rate-limits unauthenticated callers to 10 attempts per minute. Lets the CLI pair via QR code to get a device token.

🔄 Config Reload

Watches ~/.openclaw/config.json. When it changes, the gateway reloads channel connections and agent config without restarting.

⚠️

One gateway = one control plane. Only one gateway process should run at a time on a machine. If you start a second, it will fail on the port or the lock file and exit cleanly.

export type ResolveAgentRouteInput = {
  cfg: OpenClawConfig;
  channel: string;       // "telegram"
  accountId?: string;    // which account
  peer?: RoutePeer;      // who sent it
  parentPeer?: RoutePeer; // thread parent
  guildId?: string;      // Discord server
  memberRoleIds?: string[];
};

export type ResolvedAgentRoute = {
  agentId: string;        // "default"
  sessionKey: string;    // unique session ID
  mainSessionKey: string; // DM collapse key
  matchedBy: MatchReason; // why this route
};
Plain English
  • The input describes who sent the message: which channel (e.g., "telegram"), which platform account, which user (peer), and whether it's inside a thread.
  • The output is a decision: "Send this to agent X, using session key Y."
  • agentId is the name of the AI agent ("default", "work", etc.) that should handle this message.
  • sessionKey is the unique ID for this conversation thread — the agent's memory is scoped to this key.
  • matchedBy tells you why this agent was chosen, useful for debugging ("binding.peer" means the user was explicitly mapped to an agent).

Binding Priority (highest wins)

2 Thread parent binding binding.peer.parent Reply in thread inherits parent's agent
3 Discord roles binding.guild+roles @admin role → "ops" agent
4 Guild / server binding.guild Discord server → "community" agent
5 Team / workspace binding.team Slack workspace → "work" agent
6 Account binding.account Secondary WhatsApp number → agent
7 Channel default binding.channel All iMessage → "home" agent
8 System default default Anyone else → "default" agent

Quiz

A Slack user in a workspace sends a message. That same user also has a direct peer binding configured. Which route wins?

✅ Correct. Peer bindings (priority 1) always win over team bindings (priority 5). The priority table is evaluated top-to-bottom and stops at the first match. This is by design: explicit user-level bindings should always override group-level defaults.

src/channels/plugins/index.ts (simplified)
type ChannelPlugin = {
  id: string;         // "telegram", "discord"
  connect: (
    cfg: OpenClawConfig,
    onMessage: MessageHandler
  ) => Promise<ChannelConnection>;
  send: (
    connection: ChannelConnection,
    msg: OutboundMessage
  ) => Promise<void>;
  disconnect: () => Promise<void>;
};
Plain English
  • Every channel plugin has the same three-method contract: connect, send, and disconnect.
  • connect opens the connection and registers an onMessage callback — when the user sends anything, this fires with the message details.
  • send delivers an AI-generated reply back to the right user on that platform.
  • disconnect closes the connection cleanly (used on shutdown or config reload).
  • The gateway only calls these three methods — it doesn't need to know anything about WhatsApp's internals vs Telegram's internals.

Channel Health Monitor

Because messaging platforms can drop connections silently, a health monitor runs in the background:

1
Heartbeat ping every 60s
Each channel plugin reports "alive" or a last-seen timestamp.
2
Detect stale channel
If a channel hasn't responded within its timeout window, it's marked degraded.
3
Reconnect with backoff
The gateway tries to reconnect with exponential backoff — 5s, 10s, 20s…
4
Status visible on CLI
Run openclaw channels status to see live health of all channels.
Quiz

A user messages from WhatsApp. Two hours later, the same user messages from Telegram. Do the two conversations share memory?

✅ Correct. Session keys include both channel and peer ID by default, so WhatsApp and Telegram create different sessions. But if you configure a peer binding that maps both to the same agent + session key, or use session merging, the histories can be shared. The design is explicit: you opt in to shared memory; it's not automatic.

src/agents/pi-embedded-runner/runs.ts
export function queueEmbeddedPiMessage(
  sessionId: string,
  text: string
): boolean {
  const handle = ACTIVE_EMBEDDED_RUNS.get(sessionId);
  if (!handle) {
    diag.debug(`no active run for ${sessionId}`);
    return false;
  }
  if (handle.isCompacting()) {
    // Context window is being trimmed — wait
    return false;
  }
  void handle.queueMessage(text);
  return true;
}
Plain English
  • Each active conversation is an "embedded run" — a live agent loop that can receive messages while already running.
  • Messages can arrive while the agent is mid-stream (e.g. you send a follow-up while it's still replying). They get queued and processed in order.
  • If the agent is currently compacting (trimming old messages to fit the context window), new messages wait — no data loss, just a short hold.
  • Returning false means the message wasn't queued (no active session). The caller then spawns a fresh session.

What the Agent Can Do (Tools)

🖥️ Bash

Execute shell commands on your machine. Requires explicit approval by default — a security gate you can configure per-command or globally.

📁 Files

Read and write files on the gateway host. Scoped to allowed directories defined in config.

🌐 Web Search

Search the web via Brave, Exa, DuckDuckGo, or other search providers installed as plugins.

🖼️ Image Gen

Generate images via fal.ai, Replicate, or other image providers. Image is sent back to the originating channel.

🔗 Skills

User-defined skills (markdown files with instructions) that extend the agent's knowledge for specific tasks.

🤖 Sub-agents

Spawn child agents (ACP) for parallel work or specialized tasks. Results flow back to the parent session.

🔒

Bash tool approval flow. When the agent wants to run a shell command, it sends an approval request to the connected client (CLI or app). The user gets a diff-style preview and can Approve, Deny, or Always-allow. This is the core security model — you stay in control.

Quiz

A user is chatting with the agent, and it's streaming a long reply. The user sends another message mid-stream. What happens?

✅ Correct. queueEmbeddedPiMessage adds the new message to the active run's internal queue. The agent processes it immediately after finishing the current turn. This design avoids race conditions and ensures conversation continuity even when messages arrive rapidly.
MODULE 5

The Plugin System — Adding New Powers

OpenClaw's plugin system lets you add new channelsChannel plugins add new messaging platforms. They live in extensions/ and expose connect/send/disconnect., model providers, tools, and skills — without touching core code. Plugins are standard npm packages.

extensions/discord/openclaw.plugin.json
{
  "id": "discord",
  "name": "Discord",
  "version": "2026.3.1",
  "openclaw": {
    "channel": {
      "id": "discord",
      "displayName": "Discord"
    },
    "install": {
      "npmSpec": "@openclaw/discord"
    }
  }
}
Plain English
  • Every plugin declares its identity with a JSON manifest — id is the stable identifier, name is the display name.
  • The openclaw.channel section tells the gateway that this plugin provides a channel with that ID — the gateway then calls connect/send/disconnect on the plugin's exports.
  • openclaw.install.npmSpec is the npm package name used by openclaw plugins install discord.
  • Plugins are installed via npm into a dedicated plugins directory — they never pollute the core installation.

Plugin Lifecycle

1
Install
openclaw plugins install <name> — runs npm install in the plugins directory.
2
Register
On next gateway start, the plugin loader scans the plugins directory, reads the manifest, and adds the plugin to the registry.
3
Activate
The gateway calls the plugin's activate(runtime) export, injecting the plugin runtime API — config, sessions, tools, hooks.
4
Run
Channel plugins connect to their platform. Tool plugins register their tools. Hook plugins subscribe to gateway events.
5
Update / Remove
openclaw plugins update / openclaw plugins remove <name> — changes take effect on next gateway restart.

Plugin Types

📡 Channel Plugin

Connects to a messaging platform. Provides connect, send, disconnect. Examples: @openclaw/discord, @openclaw/matrix, @openclaw/msteams.

🤖 Provider Plugin

Wraps an AI API. Translates OpenClaw's model interface to the provider's SDK. Examples: @openclaw/anthropic, @openclaw/amazon-bedrock, @openclaw/deepseek.

🔧 Tool Plugin

Adds a callable tool to the agent. The agent can invoke it by name. Examples: web search, calendar integration, custom APIs.

🪝 Hook Plugin

Subscribes to gateway events: message.in, message.out, session.start, tool.exec. Use for logging, analytics, forwarding.

Quiz

You want to add Microsoft Teams support. The core repo doesn't have it. What's the correct approach?

✅ Correct. Teams support lives in extensions/msteams as a plugin package. The plugin system is designed so all channels are optional plugins — none of them are hardcoded into core. This keeps the core small and lets channels be updated independently.

🗂️ Session Transcript

Every turn (user message + assistant reply + tool calls) is saved to a JSONLJSON Lines — one JSON object per line. Easy to stream-write and stream-read without loading the whole file. file in ~/.openclaw/agents/<id>/sessions/*.jsonl. The agent loads this on each turn to remember the conversation.

⚡ Streaming

Replies stream token-by-token from the AI model through the agent, gateway, and channel — so users see the answer appearing in real time, not waiting for the full response before delivery.

🔄 Config Hot-Reload

Edit ~/.openclaw/config.json and save. The gateway detects the change, validates the new config, and reconnects any channels that changed — without a restart or dropped messages.

🌲 Context Compaction

When a conversation grows too long for the AI's context window, the agent compacts: it summarizes old turns into a dense block and trims the transcript. Your conversation continues seamlessly.

🗺️

Where to look when something breaks. Wrong reply? Check agent bindings in config. No reply at all? Check openclaw channels status for disconnected channels. Slow reply? Check model timeout settings. Bash tool not running? Check approval policy in config.

Quiz 5

A new contributor says "I want OpenClaw to support a new messaging app — which files should I change?" What's the right answer?

✅ Correct. New channels are always plugins — never hardcoded into core. Create your package under extensions/, define the openclaw.plugin.json manifest, implement the three-method channel interface, and publish to npm. Users install with openclaw plugins install <your-plugin>.
Quiz 6

OpenClaw isn't responding on Telegram, but WhatsApp works fine. Where do you look first?

✅ Correct. Since WhatsApp works, the gateway and AI model are fine. From there you'd check Telegram credentials or run a reconnect.

Glossary

Gateway

The long-running WebSocket + HTTP server that is the control plane. Runs on port 18789 by default. All channels, agents, and clients connect through it.

Agent

A named AI persona with its own system prompt, model, and conversation history. You can have multiple agents for different purposes or audiences.

Channel Plugin

An npm package that connects to one messaging platform. Exposes connect, send, disconnect. All channels are plugins — none are hardcoded into core.

Session Key

The unique identifier for a conversation thread: agentId:type:channel:peerId. The agent's memory is scoped to this key — separate keys mean separate memories.

Binding

A config rule that maps a user (peer), group (guild), or channel to a specific agent. Higher-priority bindings win. Without any binding, messages go to the default agent.

Embedded Run

An active agent session with a live AI loop. Messages are queued into it while it streams. Each session key has at most one embedded run at a time.

Context Compaction

When a conversation exceeds the AI model's context window, old turns are summarized and trimmed. The conversation continues without data loss — just compression.

ACP (Agent Control Plane)

The system for spawning child agents (sub-agents) from a parent agent. Used for parallel work or specialized tasks. Results stream back to the parent session.
